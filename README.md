# C盘清理工具 CleanC · 快速入门

> 一个 Windows 图形界面的 **C 盘清理与磁盘治理工具**：清理垃圾、找出空间到底被谁占了、卸载软件、在需要时重新划分磁盘。
> 基于 **C# / .NET 8 + WinForms**，**无第三方依赖**、纯离线运行；默认以**普通权限**启动，只在真正需要管理员时才向你申请提权。

**仓库地址：** <https://github.com/natasapaul781-tech/haflower>

## 1. 这个工具能做什么

| 你能解决的问题 | 用哪个功能 | 是否删除文件 |
|---|---|---|
| C 盘红了，想清掉临时文件和各类缓存 | [主界面清理](#61-主界面清理) | 是（需逐项确认） |
| 开发机上 `node_modules`、虚拟环境、构建产物堆满了 | [开发者环境](#62-开发者环境) | 是（需逐项确认） |
| 想卸载软件，还想把卸载后的残留一起清掉 | [软件卸载](#63-软件卸载) | 是（需逐项确认） |
| "空间到底被谁占了？"——想知道哪个目录最大 | [占用分析](#64-占用分析) | **否，纯只读** |
| C 盘空间实在不够，想把 D 盘的空间挪过来 | [磁盘分区](#65-磁盘分区) | 默认只出方案，**不动手** |
| 想知道"刚才到底删了什么" | [操作日志](#66-操作日志) | 否 |

**几个让人放心的前提：**

- **默认普通权限启动**：双击就能用，不会一上来就弹 UAC。只有勾选了系统级清理项、或点「磁盘分区」时才提示提权，取消提权也不影响其它功能。
- **先分析、后清理**：清理前必须先点「分析」看到每项能释放多少，再弹确认框。
- **删除前逐项过安全闸门**：盘根目录、`Windows`、`Program Files`、用户配置目录等一律拒绝删除（详见 [安全设计](#8-安全设计)）。
- **全程不联网**：不上传任何数据，日志也只写在本地。

## 2. 环境准备

### 只想**运行**已经编译好的程序

- Windows 10 / 11（x64 或 ARM64）
- 若使用 **单文件自带运行时版**：**无需安装任何东西**（见 [方式一](#32-方式一编译成免安装单文件版推荐)）
- 若使用**开发版**（`dotnet build` / `dotnet run` 的产物）：需要 [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)

### 想自己**编译**（从 GitHub 克隆的默认情况）

| 需要 | 说明 |
|---|---|
| **Windows 10 / 11** | 这是 WinForms 程序，只能在 Windows 上编译运行 |
| **.NET 8 SDK** | [下载地址](https://dotnet.microsoft.com/download/dotnet/8.0)（选 **SDK**，不是 Runtime） |
| **Git** | [下载地址](https://git-scm.com/download/win) |
| Visual Studio（可选） | 想用图形界面开发才需要；命令行编译不需要 |

**验证是否装好**——打开 PowerShell 或 CMD，输入：

```powershell
dotnet --list-sdks
```

只要输出里有一行以 `8.` 开头（例如 `8.0.202 [C:\Program Files\dotnet\sdk]`）就没问题。

> ⚠️ 如果报「找不到 dotnet 命令」或只有 `9.` / `10.` 开头的版本，请先安装 **.NET 8 SDK**。本项目目标框架是 `net8.0-windows`，**必须**有 8.x 的 SDK。

### 3.2 方式一：编译成"免安装单文件版"（推荐）

这条命令会把程序编译成**一个 exe 文件**，里面自带 .NET 运行时——拷到任何 Windows 10/11 电脑上都能直接双击运行，**不需要对方装 .NET**：

```powershell
cd haflower
dotnet publish main\src\CleanC\CleanC.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist
```

编译完成后，可执行文件在：

```
haflower\dist\CleanC.exe        ← 约 157 MB（自带运行时，所以体积大）
```

双击 `dist\CleanC.exe` 即可运行。**建议把这个 exe 单独复制到一个固定文件夹**（例如 `D:\Tools\CleanC\`），因为程序会在自己所在目录写日志。

> **ARM64 电脑**（如 Surface Pro X）把 `-r win-x64` 换成 `-r win-arm64`。
>
> **首次 publish 需要联网**下载运行时包（约 150 MB，之后会缓存在本机，不再重复下载）。

### 3.3 方式二：用命令行直接运行

想快速试一下，不想等 publish：

```powershell
cd haflower
dotnet run --project main\src\CleanC\CleanC.csproj -c Release
```

程序窗口会直接弹出来。

如果只想**编译**不运行：

```powershell
dotnet build main\CleanC.sln -c Release
```

> 例如 `dotnet run --project main\src\CleanC\CleanC.csproj -c Release -- --open=disk`

### 3.5 运行前必读：普通权限 vs 管理员权限

程序**默认以普通权限启动**（`asInvoker`），这是刻意的设计——否则在企业电脑上用标准账户根本打不开。

| 功能 | 普通权限 | 需要管理员 |
|---|---|---|
| 用户临时文件、各类开发缓存、浏览器缓存 | ✅ | |
| 占用分析、软件列表查看、开发者环境扫描 | ✅ | |
| 操作日志 | ✅ | |
| Windows 临时文件、Windows Update 缓存 | | ✅（勾选时会提示提权） |
| 磁盘分区（分盘 / 合盘 / 新建分区） | | ✅（点按钮时提示提权） |
| 卸载系统级软件、清理系统级残留 | | ✅ |

**提权怎么发生**：当你点了需要管理员权限的操作，会弹一个「需要管理员权限」的询问框：

- 点 **「是」**→ 弹出 UAC 确认 → 以管理员身份重新启动程序（会自动带上你的用户配置目录，保证操作的是**你**的缓存而不是管理员的）
- 点 **「否」**→ 跳过需要管理员的项，只做不需要权限的部分（不会报错中断）
- 点 **「取消」**→ 什么也不做

> 💡 如果你用的是标准账户、没有管理员凭据，所有不需要提权的功能都能正常使用，只是系统级清理和分区用不了。

## 5. 五分钟上手：清理 C 盘

**第 1 步 · 启动程序**，会先弹出一张公益捐赠海报 —— 按任意键或点一下即可关闭。

**第 2 步 · 看列表**。程序已经按推荐值**预勾选**好了安全的项目（临时文件、各类缓存），有一定风险的项目（如 `NuGet 全局包`）默认**不勾选**。

**第 3 步 · 点「分析」**。等进度条走完，`预估大小` 列会填上真实数字。这一步**不删除任何东西**。

**第 4 步 · 检查列表**。看一下：

- `预估大小` 是否符合预期（如果某一项特别大，**双击它**定位到目录看看到底是什么）
- `警告` 列有没有你不想要的后果

**第 5 步 · 点「清理选中项」**。会弹出确认框告诉你"将清理 N 项，预计释放约 X"。确认后开始清理。

**第 6 步 · 等它跑完**。清理过程中：

- 可以点 **「取消」** 中断（已经清理的部分会保留）
- 窗口会被遮罩盖住，防止你误点别的按钮
- 每个被占用的文件会**自动跳过**并记进日志，不会卡住

**第 7 步 · 看结果**。完成后程序会自动重新分析一遍，刷新每项的剩余大小和空闲空间，日志面板会写明释放了多少。

> ✅ **如果只是想看看能清多少、暂时不想删**：做到第 3 步就够了。「分析」是纯只读操作，随时可以直接关窗口。

## 6. 功能详解

### 6.1 主界面清理

主界面本身就是最常用的清理功能。

#### 完整流程

**① 勾选**——程序已按推荐值预勾选。想调整就点每一行前面的复选框，或用底部的 **`全选`** / **`全不选`**。

**② 点 `分析`**（**只读，不删任何东西**）

- 若一项都没勾，会提示「请至少勾选一个清理项。」
- 进度条右侧的 **`取消`** 按钮此时可用，随时能中断
- 分析结果填入 `预估大小` 列，顶部标签变成「预计可释放：X GB（勾选项）」

**③ 点 `清理选中项`**（真正的删除动作）

依次会遇到两道关卡：

**第一道：管理员权限**（仅当勾选了系统级项目、且当前不是管理员时）

> 所选清理项中包含需要管理员权限的项（见列表中的警告列）。
> 是否以管理员身份重启本程序？
> 点「否」则跳过这些系统级项，仅清理无需管理员的项。

选 **`是`** 会弹 UAC 重启程序（重启后带 `--user-profile` 参数，保证清理的仍是**你自己**的缓存）；选 **`否`** 跳过这些项继续清理；选 **`取消`** 什么都不做。

**第二道：确认清理**

> 将清理 N 项，预计释放约 X GB。
> 部分清理项（回收站等）为永久删除，请确认后继续。

点 `是` 才开始删除。

**④ 清理过程中**

- 窗口被遮罩盖住，防止误点；**可以点 `取消`**（已清理的部分保留，不会造成损坏）
- 每个文件逐个删除，**被占用或无权限的文件自动跳过**并记入日志，不中断整体
- 想强行关窗口会先弹一次确认：「现在关闭会中断它：已经处理完的部分会保留……不会造成损坏，但会停在半途。」

**⑤ 完成后**——程序会自动重新分析同一批项目，刷新 `预估大小` 和空闲空间，日志写明释放了多少。

#### 主界面按钮总览

| 位置 | 按钮 | 作用 |
|---|---|---|
| 左上 | `刷新空间` | 重新读取系统盘可用空间 |
| 右上 | `开发者环境` | 见 [6.2](#62-开发者环境) |
| 右上 | `软件卸载` | 见 [6.3](#63-软件卸载) |
| 右上 | `占用分析` | 见 [6.4](#64-占用分析) |
| 右上 | `磁盘分区` | 见 [6.5](#65-磁盘分区) |
| 右上 | `操作日志` | 见 [6.6](#66-操作日志) |
| 底部 | `全选` / `全不选` | 批量勾选 |
| 底部 | `分析` | 只统计，不删除 |
| 底部 | `清理选中项` | 执行删除（红色） |
| 底部 | `退出` | 关闭程序 |
| 进度条右侧 | `取消` | 中断当前分析/清理 |

#### 清理项清单

> 任何一项**目标目录不存在**就不会出现在列表里（例如没装过 Chrome 就没有 Chrome 缓存项）。
> `默认勾选` 为 ✘ 的项表示风险或代价较高，需要你自己判断后再勾。

**用户与缓存**

| 清理项 | 默认勾选 | 需管理员 | 清的是什么 / 注意 |
|---|---|---|---|
| 用户临时文件 `%TEMP%` | ✔ | | Windows 与各程序临时文件，最安全 |
| npm 缓存 | ✔ | | 下次安装需重新下载 |
| pnpm 缓存（store + cache） | ✔ | | 下次安装需重新下载 |
| pip 缓存 | ✔ | | 下次安装需重新下载 |
| NuGet HTTP 缓存 | ✔ | | 下次还原需重新下载 |
| NuGet 全局包（`.nuget\packages`） | ✘ | | 删除后项目还原需重新联网下载 |
| 缩略图缓存（`thumbcache_*.db`） | ✔ | | 被占用的跳过，图标会自动重建 |
| 崩溃转储文件（`CrashDumps`） | ✔ | | 删除后无法再分析历史崩溃现场 |

这是给开发机准备的：`node_modules`、Python 虚拟环境、`target`、`build`、各种包缓存……它们单个可能不大，加起来动辄几十 GB。

**② 点 `扫描`**——先探测已知位置，再递归遍历识别环境与产物，最后并行统计各项大小。**可以点 `取消`**。

**③ 看列表**

#### 关于「仅统计」

工具链本体、WSL/Docker 虚拟磁盘这类东西，**删了会出大事**，所以程序只告诉你"它占了多大、在哪"，**不提供删除**：

- 列表里标记为「仅统计」，**复选框点不动**
- 万一强行勾选会被拦回，并提示：
  > 请至少勾选一项可清理的条目。
  > （「仅统计」类条目——工具链本体、虚拟磁盘、AI 工具运行时等——只展示占用与位置，本工具不提供删除。）
- **删除引擎里还有第二道拒绝**，即使绕过界面也删不掉

#### 删除前的逐项校验

1. **范围校验**——删除路径必须位于本次扫描根之下，或为已知位置的精确探测路径
2. **签名复验**——重新确认目录仍是当初检测到的产物（`node_modules` 仍含 `package.json`、`venv` 仍含 `pyvenv.cfg`、`obj` 仍含 `project.assets.json`、Unity `Library` 仍含 `ArtifactDB`），不匹配就跳过
3. **符号链接拒绝**——扫描与删除均拒绝 junction / 符号链接
4. **占用自动跳过**——被占用的文件记录后跳过，不中断
5. **风险默认不勾选**——环境/依赖/全局包/构建产物类默认不勾
6. **聚合项只删缓存目录**——如 Python 字节码聚合项，逐个删它列出的缓存子目录，**绝不动承载它们的工程目录**

#### 永不进入的目录

`AppData`、`OneDrive`、`.git`、`Windows`、`Program Files`、`ProgramData`（conda envs 除外）、其他用户目录，以及 IDE / 工具链 / AI 工具自身的安装目录；**也不删除源码项目根本身**。

> 扫描项超过 800 条时，会按占用保留最大的若干条，并在日志里说明隐藏了多少。

### 6.3 软件卸载

**入口**：主界面右上角 **`软件卸载`**。打开后**自动开始扫描**，不需要点按钮。

窗口有两个标签页：**`常规软件卸载`** 和 **`深度软件卸载`**（默认停在常规页）。

#### 常规软件卸载

装的是有正规卸载程序的软件（MSI 或带 `UninstallString`）：系统安装的、用户安装的。

**① 扫描**——打开窗口即自动进行，进度条跑马灯 + 「扫描中...」。**此时可以点 `取消`**。

**② 自动实测占用**——扫描完，程序会自动对那些**注册表没有可信大小**的条目（UWP、无 `EstimatedSize`、安装位置无效的）实测目录大小。这一步只读遍历目录，**可以取消**。其余条目先用注册表估算值，显示为「约 X」。

**③ 筛选**——顶部输入框「筛选：名称 / 发布者...」，**输入即生效**，不用按回车。

> ⚠️ 筛选、排序、切换标签页都会**重建列表并清空已勾选项**，勾选后别乱动筛选框。

**④ 查看列表**

| 列 | 含义 |
|---|---|
| 名称 | 软件名（商店应用显示友好名） |
| 版本 | 版本号 |
| 来源 | `系统·64` / `系统·32` / `用户` / `商店(UWP)` / `商店(UWP)·全机` |
| 安装日期 | 从注册表读取，缺失显示 `—` |
| 占用 | **实测值优先**；`≥` 表示统计被截断；「约 X」是注册表估算值 |
| 安装位置 | 解析出的安装目录；共用目录标「（共用：X）」 |
| 数据位置 | 配置与本地数据目录（`%LOCALAPPDATA%` 等） |
| 风险说明 | 卸载这项的后果，见下 |

列表按「系统安装（需管理员）」「用户安装」分组。**勾选「按占用排序」**可在组内按占用从大到小排（默认不勾选）。

**⑤ 双击一行** → 弹出「{名称} 详情」，包含：名称、版本、发布者、来源、风险、安装日期、**占用大小与占用来源**、安装位置与位置来源、数据位置（含各自大小）、其他候选位置、卸载方式、卸载命令、静默卸载命令、MSI ProductCode、注册表项路径、UWP 包全名。想搞清楚"这软件到底占了哪、多大"就看这里。

**⑥ 卸载**——勾选要卸的软件，点 `卸载选中项`。

- 若所选里有**没有静默卸载参数**的软件，会先问一次：
  > 部分软件没有静默卸载参数，将运行其官方卸载程序（可能弹出卸载向导）。
  > 是否优先尝试静默卸载？
  > 「是」＝静默（推荐）；「否」＝全部运行官方卸载程序。
- 若所选里有**系统级软件**且当前不是管理员 → 弹「需要管理员权限」，可选提权重启 / 跳过 / 取消。
- 然后是确认框「确认卸载」，列出前 8 个软件名 + 卸载方式 + 后果说明。

**⑦ 结果复验**——卸载程序退出后，程序会**轮询检查注册表条目是否真的消失**（最多等 3 分钟），给出四种结果：

| 日志标记 | 含义 |
|---|---|
| `[完成]` | 注册表条目已消失，卸载成功 |
| `[需重启]` | 卸载完成，重启后条目才会消失（MSI 返回 3010） |
| `[未完成]` | 条目仍在 / 失败 / 不支持，会进入残留清理 |
| `[失败]` | 明确失败，附错误码（如 `1618：有另一个安装正在进行`） |

> 🛑 **卸载执行期间不能取消，也不能关窗口**。这是刻意的：中途强杀卸载程序会让软件在注册表与磁盘上状态不一致。取消只在**步骤边界**生效——已启动的卸载程序一定会被等完。

#### 深度软件卸载

装的是两类**高风险**条目：**商店(UWP)应用**、以及**没有官方卸载程序的软件**。

首次点这个标签页会先弹风险提示（选「否」不进入）：

> 深度软件卸载包含高风险操作：
> · 商店(UWP)应用：无法运行官方卸载程序，卸载后需从 Microsoft Store 重新安装；部分预装应用删除后可能影响系统功能。
> · 无官方卸载程序的软件：只能强制删除安装目录与注册表候选，可能残留引用或影响依赖它的其他软件。
> 卸载不可逆，请逐项核对列表中的「风险说明」列。

页面顶部有常驻红色警示条，确认框标题是「确认深度卸载（高风险）」，逐条列出后果。

**和常规页的区别：**

| | 常规软件卸载 | 深度软件卸载 |
|---|---|---|
| 包含 | MSI / 有官方卸载程序 | 商店(UWP) / 无官方卸载程序 |
| 分组 | 系统安装、用户安装 | 应用商店（UWP）、无官方卸载程序（仅强制删除） |
| 卸载方式 | 静默或官方程序，可选 | 恒静默（`Remove-AppxPackage` / 强制删除） |
| `全选` 按钮 | 可用 | **禁用**（防止一键批量勾选高风险项），`全不选` 仍可用 |
| 默认勾选 | 全部不勾 | 全部不勾 |

#### 残留清理

卸载跑完后，程序会检查"**官方卸载没清干净**"留下的东西，逐项列给你确认。

清单是怎么来的——只做**确定性精确匹配**，不做关键字瞎猜：

| 类别 | 匹配规则 |
|---|---|
| 注册表 | 该软件自己的卸载注册表项仍然存在 |
| 目录 | 注册表记录的安装位置仍存在；或从卸载程序路径推断出的安装目录 |
| 目录 | `%LOCALAPPDATA%`/`%APPDATA%`/`%PROGRAMDATA%` 下深度 ≤2 的目录名 == 显示名/发布者（如 `Google\Chrome` ← "Google Chrome"） |
| 快捷方式 | 桌面与开始菜单里文件名 == 显示名/发布者的 `.lnk` |
| 注册表 | `App Paths` 子键名匹配、`SOFTWARE` 根下一级子键名精确匹配 |

**安全门槛（四道）：**

1. **候选默认全部不勾选** —— 必须你自己逐项核对后手动勾
2. **入列前先过滤** —— 位置过宽的（盘根、`Program Files`、`ProgramData`、用户目录本体）直接不进列表
3. **删除前再复验一次** —— 重新过一遍安全闸门，不合格就拒绝删除
4. **删除前再弹一次确认框** —— 列出前 10 项与预计释放大小

对话框里可以看每项的 **类别 / 目标 / 占用 / 匹配规则 / 风险提示**，目录候选会实测占用并按大小降序排（目录优先）。**双击行 = 切换勾选**。

**明确不包含**（避免误导）：服务、计划任务、文件关联、Shell 扩展、开机启动项、全注册表关键字搜索——这些不在此功能范围内。程序**也不会**替你创建系统还原点，建议卸载前自己创建一个。

### 6.4 占用分析

**入口**：主界面右上角 **`占用分析`**，窗口标题「磁盘占用分析」。

**这是全工具最安全的一个窗口**——它只统计、只读，**刻意不提供任何删除按钮**。窗口自己也写着：

> 只读统计：按大小排名目录，双击逐层下钻；本窗口不提供任何删除操作。

规则扫描（注册表、已知路径）总有盲区（某个项目的临时产物、WSL 虚拟磁盘、模型缓存……），这个窗口用**通用方式**回答"空间在哪"。

#### 操作步骤

**① 选根路径**——下拉里是各固定磁盘（带卷标与"已用 / 可用"），最后一项是 `选择目录…`，可以任选一个目录。

**② 选深度**——`2` / `3` / `4`（默认）/ `5`。

**③ 点 `开始分析`**——进度条与日志实时更新，**可以点 `取消`**。

**④ 看排名**——列表按大小降序列出当前层的子目录：

| 列 | 含义 |
|---|---|
| 大小 | 该目录的合计占用 |
| 占比 | 占根路径的比例 |
| 文件数 | 文件数量 |
| 子目录 | 子目录数量 |
| 最后修改 | 最近修改时间 |
| 路径 | 完整路径 |

> 列表里可能有一行「（根目录直属文件）」——那表示**根目录下不属于任何子目录的文件**合计。它没有子目录，所以**不能下钻**。

**⑤ 逐层下钻**——**双击目录行**进入下一层：

- 顶部面包屑显示当前路径
- `上一级` 回到上一层
- `回到根` 直接回根视图
- 已经在深度上限的目录，双击会**就地重新分析并展开**（把它当作新的根继续往下看）

**⑥ 带走结果**

| 按钮 | 作用 |
|---|---|
| `复制路径` | 把选中行的路径复制到剪贴板（方便去资源管理器定位） |
| `导出 CSV` | 导出当前视图排序后的清单（UTF-8 带 BOM，Excel 打开不乱码） |

#### 统计口径（重要，看数字前先读）

窗口底部有一条常驻提示：

> 本窗口仅统计，不提供删除；硬链接（WinSxS）、压缩/去重存储按逻辑大小统计，可能高于实际占用；无权限目录与联接（junction）已跳过并计数。如需清理请使用主界面 / 开发者环境 / 软件卸载窗口。

具体口径：

| 口径 | 说明 |
|---|---|
| **单遍遍历、只读** | 不移动、不删除任何文件 |
| **不跟随联接/符号链接** | `C:\Users\All Users`、`AppData\Local\Application Data` 等 junction 既不计入也不下探（否则会重复计数甚至死循环）；跳过数量在日志与汇总里给出 |
| **无权限目录跳过并计数** | `WindowsApps`、其他用户目录等；以管理员身份运行结果更完整 |
| **隐藏/系统文件计入** | 如 `pagefile.sys`、`hiberfil.sys`，便于和"卷已用"对得上 |
| **逻辑大小** | 硬链接（WinSxS）、NTFS 压缩、去重存储按逻辑大小累加，**可能高于物理占用**；卷已用与"统计到"的差额会在日志中说明 |
| **有大目录保护上限** | 文件数（500 万）/ 耗时（10 分钟）/ 节点数（20 万）有上限，触顶时汇总会标注「已截断（下界）」，意味着真实占用只会**大于**显示值 |

#### 为什么没有删除按钮

这是刻意的设计：**"看"和"删"分开**。

- 占用分析面对的是**任意目录**——包括你不希望被误删的工程目录、系统目录。给它配删除按钮，风险远大于便利。
- 知道自己要删什么之后，去对应的功能里删：系统缓存 → 主界面；开发产物 → 开发者环境；软件 → 软件卸载。那些地方都有**针对性**的安全校验（签名复验、范围校验、白名单）。

### 6.5 磁盘分区

> ⚠️ **这一节涉及不可逆操作，请通读后再动手。**
> 好消息是：**程序默认只产出《操作说明书》，不动你的磁盘**——要真正执行，必须你显式勾选两处确认。

**入口**：主界面右上角 **`磁盘分区`**，窗口标题「磁盘分区（分盘 / 合盘）」。

因为是普通权限启动，点这个按钮会先问一次：

> 磁盘与分区信息受系统保护，读取和执行分区操作都需要管理员权限。
> 是否以管理员身份重新启动本程序？
> 点「否」也可以继续打开该窗口，但只能看到「需要管理员权限」的说明。

选 `是` 会提权重启并**直接落在磁盘分区窗口**（这就是 `--open=disk` 参数的用途）。

#### 打开时只做只读检测

窗口打开后只做一件事：**只读探测**磁盘布局（进度显示「正在检测磁盘（只读，不会做任何改动）...」）。这一步**不创建、不删除、不调整**任何分区和文件，可以随时取消。

#### 界面导览

| 区域 | 内容 |
|---|---|
| 磁盘条带图 | 按真实起始偏移与容量**等比**画出 EFI / MSR / 各数据分区 / WinRE / 未分配区域 |
| 磁盘下拉 | 多磁盘机器可切换（**切换会清空上一个磁盘的分析结果**，防止把 A 盘的结论用到 B 盘） |
| 标签页 | **`分盘（把 C 盘分出 D 盘）`** 与 **`合盘（把 D 盘并回 C 盘）`** |
| 推荐摘要 | 一行显示「建议保留 ≥ X（下限 Y）｜ 本机最多可分出 Z｜ 新分区最小建议 W」 |
| 滑块 | 拖动调整保留多少 GB，下方实时给出白话解释（会不会太少 / 太多 / 偏低） |
| 校验结论 | 「✔ 校验全部通过」或「⛔ 阻断 N 项，另有 M 项提示」 |
| 计划步骤列表 | 列出将要执行的每一步，标注「★ 不可逆」「不可中断」；**双击某步**看该步的详细说明与等价命令 |

**条带图交互**：鼠标悬停看分区详情；**点击**分区会自动设为操作对象（系统盘 = 分盘的源 / 合盘的目标；其它可操作分区 = 合盘要合并掉的分区）。

**窗口内的按钮**：

| 按钮 | 作用 |
|---|---|
| `重新检测` | 重新只读探测磁盘 |
| `磁盘明细…` | 逐分区列出类型原文与判定理由，可复制表格 / 导出诊断 JSON |
| `环境检查…` | BitLocker、页面文件、休眠、卷影副本、系统保护状态 |
| `推荐明细…` | 推荐值怎么算出来的（4 项构成 + 本机实测范围） |
| `查看校验…` | 全部阻断项与提示项（级别 / 项目 / 说明 / 补救动作），可复制 |
| `为什么分不出空间？` | 按「收益 / 风险」排序的补救清单，逐条标注可逆性 |
| `用未分配空间新建分区…` | 括号里显示所有磁盘未分配空间的合计；打开独立窗口 |
| `查看日志…` | 本次会话日志（持久化日志见主界面「操作日志」） |
| `生成说明书` | **默认交付物**，导出到桌面 |
| `以管理员身份重新启动` | 未提权时出现 |

#### 推荐值怎么算（全部按本机实测，不写死数字）

```
已用          = 卷容量 − 剩余空间
Windows 更新与系统保留 = +20 GB（组件存储 WinSxS / 更新下载 / 系统还原缓冲）
页面文件等     = +本卷根目录 pagefile.sys + hiberfil.sys + swapfile.sys 的实测大小
增长余量       = +max(已用的 15%, 30 GB)
按需建议值     = 已用 + 20 GB + 页面文件等 + 增长余量
建议保留 ≥     = max(按需建议值, 硬下限)        ← 界面默认显示的就是它
硬下限         = max(64 GB, 已用 + max(已用的 10%, 20 GB))
新分区最小建议 = max(物理磁盘容量 × 8%, 50 GB)
```

界面额外标注两个**由 Windows 实测**决定的边界：

- **本机最多可分出** = 当前卷大小 − `GetSupportedSize` 的 `SizeMin`（Windows 按"不可移动文件"位置算出来的真实上限）
- **滑块下界（最少保留）** = max(硬下限, 卷容量 − 最多可分出)；被抬高时界面会解释「受本机可收缩能力限制」

> 为什么不用固定值：一台只剩 40 GB 已用的办公机和一台装了 400 GB 开发环境的机器，需求完全不同。

#### 分盘：三步

点 `开始执行（分盘）` 会先弹确认框「确认执行分盘」（**默认按钮是"否"**），然后依次执行：

| 步 | 做什么 | 破坏性 |
|---|---|---|
| 0 | 执行前复验分区身份（GUID + 偏移 + 大小） | 只读 |
| 1 | **收缩**源分区到目标大小 | 否（系统自动把文件挪到前部，**普通文件不会丢**）；但**发出后不可中断** |
| 2 | 在释放出的未分配空间**新建分区**并分配盘符 | 否 |
| 3 | **格式化刚创建的那个**分区为 NTFS | 否（只作用于新分区） |

- 每一步失败就**立即停止**，后续步骤标记「已跳过」，并给出可执行的恢复建议（不会留下更坏的状态）
- 第 2 步会**先实测**释放出的空间够不够（比计划少 64 MB 以上就中止）
- 第 3 步只格式化**三重身份匹配**（GUID + 偏移 + 大小）且是刚创建的分区；**绝不按盘符猜目标**

#### 合盘：两个阶段 + 三次确认

先讲清事实：Windows 内置工具**只能收缩/扩展，不能移动已有分区**，所以合盘必须**先删掉源分区**。

> 🛑 **本工具不替用户备份任何文件。** 它只负责把后果讲清楚。

| 阶段 | 做什么 | 破坏性 |
|---|---|---|
| ① 分析可行性 | 校验白名单、相邻性（目标在左、源在右、中间无其它分区）、文件系统、健康状态、BitLocker、页面文件等 | 否 |
| ② 只读盘点 | 点 `删除并扩容…` 时先**只读遍历**源分区，用**真实数字**告诉你会删掉多少：文件数、总体积、主要目录各自大小（最多 8 项） | 否（可随时取消） |
| ③ 风险确认 | 弹出危险确认窗：真实数字 + 「本工具不会替你备份任何文件」+ 不备份的具体后果 + 建议先做的三件事 | — |
| ④ 最后一次确认 | 再弹一次，说明将永久删除且此后无法撤销 | — |
| ⑤ 删除 + 扩容 | 删除源分区 → **先实测**相邻空闲空间不少于源分区容量 → 并入目标分区 | **是（不可逆）** |

**第 ③ 步的确认窗是本工具最谨慎的地方**：

- **销毁按钮默认禁用**，必须先勾选「我已确认 D: 里的文件不再需要，或已自行备份到其它位置并能正常打开」
- **默认按钮是「取消（我要先备份）」**，**回车和 Esc 都是取消**
- 勾选后才会进入第 ④ 步的最后一次确认

**删除前仍会强制拦下**（这些不是备份，是"别把系统弄坏"的底线）：

- 源分区是 Windows 所在分区 / 启动分区 → 阻断
- 源分区根目录有 `pagefile.sys` / `hiberfil.sys` / `swapfile.sys` → 阻断（先移走页面文件、`powercfg /h off` 关休眠）
- 源分区里**正放着本程序**（`CleanC.exe`）→ 阻断，否则程序会在操作中途把自己删掉
- 目标与源不在同一磁盘、源在目标左侧、两者之间还有其它分区 → 阻断
- 白名单之外的分区类型（EFI / MSR / WinRE / 动态磁盘 / 存储池）→ **永不进入可选列表**

删除与扩容两步的等价命令都会**先复验分区身份**，扩容前还会实测相邻空闲空间，避免"删了分区却扩不了容"。

#### 新建分区：把"未分配"空间用起来

从 `用未分配空间新建分区…` 按钮进入（独立窗口）。它做两件事：**在已经空着的空间里建一个分区，然后格式化为 NTFS**。

它不收缩、不删除、不移动任何现有分区，所以风险低得多，但仍有几条硬规矩：

1. **磁盘开头和末尾各留 1 MB** —— 那是 GPT 主分区表和备份分区表的位置；用满到最后一字节会被系统拒绝
2. **起点按 1 MB 向上对齐、尺寸向下取整到 1 MB** —— Windows 会直接拒绝未对齐或"除不尽 1 MB"的请求
3. **执行前重新枚举该磁盘的分区**，确认那段空间此刻仍然空着（计划可能是几分钟前生成的），重叠即中止
4. **显式指定起始偏移**，创建后核对实际偏移，避免"以为建在这里、其实建在别处"
5. **只格式化三重身份匹配的新分区**，绝不按盘符猜目标

界面上的 `用满整段` 按钮会把大小一次拉到最大；默认选**最大**的那段空闲空间。

#### 《操作说明书》：默认交付物

点 `生成说明书` 会导出一份纯文本说明到**桌面**（UTF-8 带 BOM，记事本打开不乱码），文件名形如 `CleanC-分区说明-20261007-093012.txt`。

内容包含：本机磁盘现状（含纯文本条带图）→ 本次方案与推荐值构成 → 分步操作（每步「做什么 / 预期结果 / 出错了怎么办」）→ **可复制的等价 PowerShell 命令** → 出问题时的恢复指引 → 名词解释。

**保存位置的回退顺序**：桌面 → 文档 → 程序所在目录（每一级都会**实际写盘探测**，全不可写才报错；**绝不写相对路径**——那可能落到 System32）。

> 💡 你完全可以**只用说明书**，然后在 Windows 自带的「磁盘管理」里自己操作，不必让本工具执行。

#### 想让工具执行？两道锁

```csharp
执行按钮可用 = 有合法计划 && 已提权 && 已勾风险确认 && 已勾「我已阅读说明书，确认由本工具执行上面的步骤」
```

没勾选时状态行会明确告诉你缺什么，例如：

- 「请先勾选上方的风险确认。」
- 「请勾选『我已阅读说明书，确认由本工具执行』。（也可以只用说明书，在系统『磁盘管理』里自己操作）」

**执行期间是"不可中断档"**：遮罩显示红色警示「⚠ 危险操作进行中：请不要关闭窗口、不要断电、不要强制关机」，**不提供取消按钮**，「返回」按钮也被禁用，关窗口会被拒绝（连续尝试 3 次后才提示可用任务管理器，并说明风险）。

> 「取消」只在**步骤边界**生效——收缩/删除/扩容一旦发出**绝不杀子进程**，因为中途打断分区操作是危险的。

#### 分区日志

分区相关的操作会以这些类别写入 `operations.log`：

`分区-探测`、`分区-计划`、`分区-步骤`、`分区-结果`、`分区-删除`、`分区-分盘`、`分区-合盘`、`分区-新建`、`分区-说明书`、`分区-诊断`

每一步都记录**前状态 → 后状态**与 Windows 返回码；删除前还会记录"将删除 N 个文件 / X GB"——**删除之后这是唯一的可追溯线索**。

### 6.6 操作日志

**入口**：主界面右上角 **`操作日志`**。

#### 日志文件在哪

**在程序自己所在的目录**（exe 旁边）：

```
<程序目录>\operations.log
```

例如你把 `CleanC.exe` 放在 `D:\Tools\CleanC\`，日志就是 `D:\Tools\CleanC\operations.log`。**日志跟着程序走**，拷走或卸载工具时一并带走，不用去别处找。

> 如果程序目录不可写（例如你把工具装到了 `C:\Program Files\` 且以普通权限运行），程序会**自动退到** `%LOCALAPPDATA%\CleanC\operations.log`，不会因此丢日志。查看器窗口顶部会显示当前实际使用的完整路径。

#### 记录了什么

所有**破坏性 / 关键操作**都会自动带时间戳写进去：

- 主界面清理（项数、释放大小、错误数）
- 开发者环境删除
- 软件卸载结果（成功 / 需重启 / 未完成及详情）
- 残留清理明细
- 磁盘分区全过程（探测、计划、每一步的前后状态与返回码、删除前的"将删除 N 个文件 / X GB"）
- 每次启动的用户上下文与权限状态

#### 窗口里的操作

| 按钮 | 作用 |
|---|---|
| `刷新` | 重新读取日志 |
| `导出副本…` | 另存为 txt（可另存为完整历史） |
| `清空日志` | 清空全部记录（**会先弹确认框**） |
| `关闭` | 关窗 |

#### 维护策略

- 单次读取上限 **2000 行 / 1 MB**（窗口不会因为日志太大而卡死）
- 文件超过 **2 MB** 自动轮转，保留一份 `.old`
- 写入是"尽力而为"：文件被占用或无权限时**静默跳过**，绝不影响清理/卸载主流程
- **纯本地取证用途，不联网、不上传**

## 8. 安全设计

这一节回答一个最实际的问题：**"它会不会误删我的东西？"**

### 每一处删除都有拦截

| 机制 | 说明 |
|---|---|
| **先分析后清理** | 删除前必须先在列表里看到每项预估大小，再弹确认框 |
| **逐项二次确认** | 卸载、开发环境删除、残留清理、分区执行，全部有独立确认框 |
| **安全闸门（列出时 + 动手前各查一次）** | 所有递归删除在**列出目标时**和**真正删除前**各校验一次，命中即拒绝并写明原因 |
| **符号链接拒绝** | 统计与删除都不跟随 junction / 符号链接，避免重复计数与越界删除 |
| **被占用文件自动跳过** | 逐个文件删除，锁定或无权限的文件记录到日志后跳过，不中断整体 |
| **范围校验** | 开发环境的删除路径必须位于本次扫描根之下 |
| **签名复验** | 删除时重新确认目录仍是当初检测到的产物（如 `node_modules` 仍含 `package.json`、`venv` 仍含 `pyvenv.cfg`） |
| **风险项默认不勾选** | 环境/依赖/全局包/构建产物类默认不勾，警告列写明"需重新安装/重建" |
| **仅统计项永不可删** | 工具链本体、WSL/Docker 虚拟磁盘只列占用，不提供删除入口（UI 与引擎双重拦截） |

### 一律拒绝删除的位置

命中任一条就**拒绝执行**并写明原因：

- **盘根目录**与 UNC 共享根（`C:\`、`D:\`、`\\server\share`）
- **Windows 目录**及其整个子树（仅放行 `Windows\Temp` 与 `SoftwareDistribution\Download`）
- `Program Files` / `Program Files (x86)` / `ProgramData` / `Users` **本体**
- **任意用户**的配置目录本体及其下的 `Desktop` / `Documents` / `Downloads` / `AppData` / `OneDrive`
- **程序自身所在目录**
- 相对路径与空路径

> 为什么这么严：不少删除目标来自**本机环境**而不是写死的常量。例如 `GOCACHE=D:\`、注册表把 `D:\` 写成安装位置、`TEMP` 缺失时 `Path.GetTempPath()` 返回 **Windows 目录** —— 这些以前会变成"清空整盘 / 清空 Windows 的目标"。

### 绝不碰你的个人文件

- 下载、桌面、文档等个人目录**不在清理范围**
- 第三方缓存只清"命名即缓存"的标准子目录，**绝不清理**：聊天记录、浏览器书签/密码/历史、下载与接收的文件、游戏本体与存档、软件安装目录
- 「占用分析」窗口**刻意不提供删除按钮**——它是只读统计工具

### 统计一律只读

软件占用实测、开发者环境大小、残留占用、磁盘占用分析——**全部只读取目录信息**，不修改、不删除任何文件。分区窗口打开时也只做只读检测。

### 不打断系统调用

- 分区操作（收缩 / 删除 / 扩容）一旦发出**绝不 kill 子进程**，取消只在**步骤边界**生效
- 卸载过程中**绝不强制终止已启动的卸载程序**——中途打断可能损坏系统状态
- 危险操作期间**窗口关不掉**（×、Alt+F4、任务栏关闭全部拦下），避免留下半完成状态

### 本工具**不做**的事

- ❌ 不碰 Prefetch、WinSxS（组件存储）、系统还原点、休眠文件（这些建议用系统自带「磁盘清理」或 DISM）
- ❌ 不替用户备份任何文件（分区操作只把后果讲清楚）
- ❌ 不做"分区左移"（那需要搬移整块分区，风险太高）
- ❌ 不做 MBR↔GPT 转换，不删除 WinRE 分区来给 C 盘扩容
- ❌ 不做全注册表关键字扫描

## 9. 常见问题

<details>
<summary><b>双击没反应 / 提示缺少 .NET？</b></summary>

你运行的是**框架依赖版**（`dotnet build` 的产物，约 141 KB）。装一下 [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)，或者改用[方式一](#32-方式一编译成免安装单文件版推荐)编译自带运行时的单文件版。

</details>

<details>
<summary><b>为什么每次启动都弹捐赠海报？可以关掉吗？</b></summary>

这是作者加的公益展示。**按任意键或点击窗口任意位置**即可关闭，不影响任何功能，也不会重复弹出（一次启动只弹一次）。

</details>

<details>
<summary><b>程序会联网上传我的数据吗？</b></summary>

不会。全部功能纯本地运行，日志只写在本地（程序目录下的 `operations.log`）。唯一联网的场景是你自己用 `dotnet publish` 首次拉取运行时包。

</details>

<details>
<summary><b>日志文件在哪？为什么找不到？</b></summary>

在**程序自己所在目录**（`CleanC.exe` 旁边）的 `operations.log`。如果程序目录不可写（例如装在 `C:\Program Files\`），会自动退到 `%LOCALAPPDATA%\CleanC\operations.log`。打开「操作日志」窗口，顶部会显示当前实际路径。

</details>

<details>
<summary><b>为什么有些清理项没出现？</b></summary>

两项过滤：**目标目录不存在**的项不会列出（比如没装 Chrome 就没有 Chrome 缓存项）；命中**安全闸门**（盘根、Windows 目录、用户配置目录等）的项会被剔除，并写入日志说明原因。想看"为什么某项没出现"，去操作日志里搜「已跳过」。

</details>

<details>
<summary><b>清理时有文件删不掉，会中断吗？</b></summary>

不会。被占用或无权限的文件会被**跳过并记入日志**，整体继续执行。完成后日志会汇总提示有多少项被跳过。

</details>

<details>
<summary><b>需要在企业电脑上用（标准账户、没有管理员凭据）？</b></summary>

可以直接用。程序默认普通权限启动，**大部分功能都不需要管理员**（用户临时文件、各类开发缓存、浏览器缓存、占用分析、软件列表、开发者环境扫描、操作日志）。只有系统级清理和磁盘分区用不了——点了会提示，你可以选「否」跳过。

</details>

<details>
<summary><b>磁盘分区能撤销吗？</b></summary>

- **分盘（收缩 + 新建 + 格式化）**：收缩不删文件；想撤销可以把新分区删掉，再对原分区「扩展卷」（说明书里有等价命令）。
- **合盘（删除源分区）**：**不可撤销**。删除后文件将无法访问——这比格式化更彻底（分区表条目被移除，资源管理器里连盘符都不再出现）。Windows 没有撤销；数据恢复软件只有在删除后**没有向这块磁盘写入任何新数据**时才可能成功，且成功率不保证。

**所以请在工具之外自行备份。**

</details>

<details>
<summary><b>它说要"以管理员身份重新启动"，重启后我的缓存会被清错吗？</b></summary>

不会。提权重启时会带上 `--user-profile=<你的用户配置目录>` 参数，即使 UAC 用的是**另一个管理员账户**，工具仍然只清理/分析**你自己**的缓存与目录。

</details>

<details>
<summary><b>能清理 WinSxS、系统还原点、休眠文件吗？</b></summary>

**不能，这是刻意的。** 这些属于"深度清理"，风险更高，建议用系统自带的「磁盘清理」或 `DISM` 处理。如果你要腾出分区空间，分区窗口的「为什么分不出空间？」会告诉你关闭休眠 / 调整页面文件能省多少（按本机实测给出数字）。

</details>

<details>
<summary><b>编译时报错 <code>NETSDK1045</code> 或找不到 net8.0-windows？</b></summary>

你没有装 .NET **8** SDK（可能只装了更高版本）。本项目目标框架固定为 `net8.0-windows`，请安装 .NET 8 SDK 后再编译。用 `dotnet --list-sdks` 确认有一行以 `8.` 开头。

</details>
